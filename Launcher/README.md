# Widget Launcher

Лаунчер для виджетов рабочего стола Windows. Первый доступный виджет — Mini Player. Каталог читает отдельный список пакетов, поэтому следующие виджеты можно добавлять без перестройки интерфейса.

## Установка и использование

1. Запустите **WidgetLauncher-Setup.exe**.
2. Выберите отдельную папку на локальном диске и нажмите **Установить**. Подойдёт папка по умолчанию или, например, `D:\WidgetLauncher`. Папка должна быть доступна для записи вашему пользователю.
3. Откройте лаунчер и нажмите **Установить** на карточке мини-плеера.
4. Нажмите **Запустить**. Закрытие лаунчера оставляет виджет работающим; настройки открываются с карточки или из самого плеера.

Установщик содержит необходимые компоненты .NET 10 x64. Во время установки и установки мини-плеера интернет не требуется. Создаются ярлыки на рабочем столе и в меню «Пуск», а также запись в списке установленных приложений Windows.

Сейчас в каталоге доступен мини-плеер. Карточка будущих виджетов сообщает о дальнейшем расширении; готовых модулей OBS в этой версии нет. Онлайн-каталог и автоматическое обновление ещё не подключены.

## Расположение файлов

```text
Выбранная папка/
  Launcher.exe
  Uninstall.exe
  Runtime/                 компоненты запуска, общие для лаунчера и виджетов
  Catalog/widgets.json     каталог
  Packages/mini-player.zip пакет для установки мини-плеера
  Widgets/mini-player/App/ установленный мини-плеер
  Data/mini-player/        настройки, оформление и горячие клавиши
```

При первом запуске мини-плеер копирует прежние настройки из `%LOCALAPPDATA%\MiniPlayer`, если в новой папке их ещё нет. Исходные настройки остаются на месте. Старую отдельную версию плеера лучше закрыть через её значок возле часов перед запуском новой.

Удаление виджета из лаунчера сохраняет его настройки для повторной установки. Кнопка удаления в настройках управляемого мини-плеера открывает эту же операцию в лаунчере. Полное удаление лаунчера доступно в его настройках и в установленных приложениях Windows; после подтверждения удаляются также установленные виджеты и их данные. Посторонние файлы в выбранной папке сохраняются.

Для обновления самого лаунчера завершите его и плеер через меню возле часов, затем запустите новый установщик и укажите прежнюю папку. Установленные виджеты и их настройки сохранятся. Обновление пакета плеера применяется при его повторной установке из каталога.

## Сборка

Сборка выполняется на Windows x64 с PowerShell 7 (с библиотеками Roslyn), .NET Desktop Runtime 10 и стандартным .NET Framework Windows. SDK для комплектного сценария сборки не требуется.

Из корня репозитория:

```powershell
pwsh -NoProfile -File .\Build-Launcher.ps1
```

При первой сборке скачиваются два официальных архива среды Microsoft 10.0.15. Перед распаковкой проверяются закреплённые SHA-512. Лицензии среды поставляются внутри папки Runtime. Готовый установщик появляется в `dist\WidgetLauncher-Setup.exe`; промежуточные файлы — в `.build`. Ключ `-RuntimeCache` позволяет использовать заранее скачанные архивы.

`Launcher\Launcher.csproj` и `Source\MiniPlayer.csproj` также содержат проекты для разработки с .NET SDK 10. Общий сценарий формирует пакет виджета, добавляет закрытую среду запуска, собирает оболочку запуска и один установочный EXE.

## Добавление виджетов

Каталог — массив объектов с полями `Id`, `Name`, `Description`, `Version`, `Package`, `Executable`, `Available`. `Id` — имя подпапки в `Widgets` и `Data`; пакет задаётся относительно `Packages`, исполняемый файл — относительно папки виджета. Пакеты распаковываются только внутрь папки виджета; абсолютные пути, переходы к родителю и ссылки отклоняются.

Текущий протокол запуска рассчитан на управляемые .NET-виджеты: среда запускает DLL рядом с EXE и передаёт `--data-dir`, `--launcher-root`, `--show-existing`. Для новых типов виджетов, включая OBS, потребуется отдельный адаптер запуска. Состояние экземпляра и команды закрытия/показа используют именованные объекты Windows; пример реализации находится в `Source\LauncherIntegration.cs`.

## Проверка

```powershell
pwsh -File .\Tests\Test-WidgetManager.ps1
pwsh -File .\Tests\Test-Installer.ps1
```

Проверки создают отдельные временные каталоги; установка и удаление в тестовом режиме не создают личные ярлыки и записи Windows. Проверяются установка в выбранную папку, повторная установка, сохранение данных, откат при занятом файле, защита границ путей и сохранение посторонних файлов.
