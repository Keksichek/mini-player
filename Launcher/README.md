# VibeWidgetsHub alpha

Версия лаунчера **0.3**, мини-плеера **0.1**.

Лаунчер для виджетов рабочего стола Windows. Первый доступный виджет — Mini Player. Каталог читает отдельный список пакетов, поэтому следующие виджеты можно добавлять без перестройки интерфейса.

## Установка и использование

1. Запустите **WidgetLauncher-Setup.exe**.
2. Выберите папку на локальном диске и нажмите **Установить**. Например, при выборе `D:\Приложения` установщик сам создаст `D:\Приложения\VibeWidgetsHub alpha`. По умолчанию папка хаба создаётся внутри `%LOCALAPPDATA%`. Выбранное место должно быть доступно для записи вашему пользователю.
3. Откройте лаунчер и нажмите **Установить** на карточке мини-плеера.
4. Нажмите **Запустить**. Закрытие лаунчера оставляет виджет работающим; настройки открываются с карточки или из самого плеера.

Установщик содержит необходимые компоненты .NET 10 x64. Во время установки и установки мини-плеера интернет не требуется. Создаются ярлыки на рабочем столе и в меню «Пуск», а также запись в списке установленных приложений Windows.

Сейчас в каталоге доступен мини-плеер. Новые виджеты появляются вместе с обновлениями хаба. Для OBS пока предусмотрен раздел с анонсом.

## Общие настройки хаба

В **Настройках → Автозапуск** доступны выключение и четыре режима входа в Windows:

- **Полностью** — лаунчер и все установленные виджеты.
- **Только виджеты** — все установленные виджеты без открытия лаунчера.
- **Только выбранные виджеты** — отмеченные элементы из «Моих виджетов», без лаунчера.
- **Почти полностью** — лаунчер и отмеченные виджеты.

В двух выборочных режимах ниже появляется список установленных виджетов. Если список выбора пуст, режим «почти полностью» запускает только лаунчер; режим «только выбранные» ничего не открывает. Уже работающий виджет повторно не запускается. Автозапуск относится к текущему пользователю Windows.

Значок солнца/луны рядом с **alpha** переключает дневной и ночной интерфейс. Выбор сохраняется и сразу применяется к открытым настройкам и оформлению мини-плеера, сохраняя несохранённые изменения темы виджета. Само оформление корпуса плеера выбирается отдельно.

Тумблер **Границы экрана** разрешает или запрещает виджетам выходить за края монитора. При выключении плеер сразу возвращается в рабочую область и ограничивает перемещение её границами. По умолчанию выход за экран разрешён.

Общие настройки хранятся в `Data/hub-settings.json` внутри папки хаба.

При нажатии крестика лаунчер предлагает **В трей** или **Закрыть полностью**. Флажок **Не показывать больше** запоминает выбранное действие. В разделе **Настройки → Закрытие окна** можно снова включить вопрос, выбрать постоянное сворачивание в трей или завершение лаунчера. Работающие виджеты при обоих вариантах продолжают работать.

Лаунчер из трея возвращается двойным щелчком по его значку или через пункт **Открыть лаунчер**; там же доступны настройки и полное завершение. Удаление, перенос и завершение сеанса Windows обходят вопрос при закрытии.

## Перенос всей установки

В **Настройках → Папка лаунчера → Перенести всё…** выберите новую родительскую папку. Хаб создаст внутри неё `VibeWidgetsHub alpha`, перенесёт лаунчер, все виджеты и их настройки. Для переноса нужна пустая папка назначения; объединение с другой установкой не выполняется.

После подтверждения хаб и работающие виджеты закрываются. Отдельная программа переноса копирует и проверяет файлы, обновляет пути запуска, ярлыки, запись удаления и включённый автозапуск, затем открывает лаунчер и ранее работавшие виджеты из нового места. Исходные файлы удаляются после проверки новой копии; занятые или изменившиеся файлы сохраняются в старой папке с уведомлением.

## Обновления из GitHub и локальной папки

В **Настройках → Обновления** по умолчанию выбран **GitHub**. Нажмите **Проверить обновления**: хаб проверит опубликованные релизы `Keksichek/mini-player`, относящиеся к ветке `secondary`. Если найдена более новая подписанная сборка, появится кнопка **Обновить** и описание изменений. При проверке скачивается только описание; сам пакет загружается после нажатия **Обновить**, с прогрессом и возможностью отмены.

Переключатель **Автообновление: ВКЛ/ВЫКЛ** по умолчанию выключен. Если включить его, хаб проверяет GitHub после запуска и каждые 6 часов, скачивает и устанавливает новую сборку, затем возвращает работающие виджеты. Выключение во время сетевой загрузки отменяет её. Уже начатая замена файлов завершается с проверкой запуска или откатом. Неудачная сборка не устанавливается автоматически повторно; ручная попытка остаётся доступной.

Для локальной проверки выберите **Локальная папка**, укажите папку пакета и нажмите **Проверить обновления**. Установщик и пакет из одной сборки имеют одинаковый номер. Кнопка **Обновить** появится, когда номер в пакете выше установленного.

Пакет обновления содержит `update.json`, `update.sig` и `payload.zip`. Проверяются подпись описания, канал `secondary-local`, размер и SHA-256 пакета. Название канала сохранено для совместимости с прежними локальными сборками; оно не ограничивает способ доставки. Номер сборки сравнивается отдельно от отображаемой версии лаунчера **0.3**, поэтому несколько исправлений могут иметь одну версию и разные номера сборок.

Обновление включает каталог `Catalog/widgets.json`, пакеты доступных виджетов и файлы хаба. Поэтому новые виджеты появляются в каталоге после обновления хаба, а уже установленные виджеты обновляются вместе с ним. Новые виджеты автоматически не устанавливаются.

Обновление закрывает хаб и виджеты, сохраняет резервные копии и заменяет файлы лаунчера и уже установленных виджетов. Папка `Data` не входит в пакет обновления. Новая версия должна подтвердить загрузку интерфейса и запуск ранее работавших виджетов. При ошибке установки или этой проверки восстанавливаются предыдущие файлы и настройки. Это проверка запуска, а не гарантия отсутствия любых ошибок новой версии.

Журнал незавершённой операции находится в `.update-transaction`. Если обновление было прервано, следующий запуск `Launcher.exe` запускает восстановление. Не удаляйте эту папку вручную во время операции. Изменённые данные неудачной версии могут быть сохранены отдельно в `.update-preserved-*`.

Для подготовки пакета после сборки:

```powershell
pwsh -File .\Build-Launcher.ps1
pwsh -File .\Build-Update.ps1 -Notes 'Описание изменений'
```

Готовая папка — `dist/local-update`. `Build-Update.ps1` подписывает её локальным ключом `.build/update-signing/private.xml`; этот файл нельзя включать в установщик, пакет обновления или исходный архив для публикации. Публичный ключ проверки хранится в `Shared/UpdatePublicKey.xml` и встроен в лаунчер и программу обновления. Сохраните приватный ключ отдельно: без него нельзя выпустить новое обновление для уже установленных копий. Сценарий отказывается незаметно менять доверенный ключ.

Для будущей публикации загрузите **все три файла из одной сборки** в GitHub Release с `target_commitish: secondary`. Одного `WidgetLauncher-Setup.exe` недостаточно для автообновления. Черновики и релизы с другой целевой веткой игнорируются. Сценарии сборки и сам хаб ничего не публикуют на GitHub; публикация выполняется отдельно.

## Кастомизация лаунчера

Вкладка **Кастомизация** содержит четыре блока без нумерации: **Готовые пресеты**, **Создать свой пресет**, **Рандомизировать**, **Созданные пресеты**. Каждый сначала предлагает выбрать виджет. Для мини-плеера доступны все 14 тем из его окна оформления с исходными миниатюрами; свои варианты находятся в четвёртом блоке.

Конфигуратор создаёт свободный макет на основе палитры темы: 11 форм корпуса (включая звезду, квадрат, круг, ромб, шестиугольник и сердце), размеры, скругление, рамка, непрозрачность и четыре цвета. У круга равные стороны; переход к овалу восстанавливает независимые ширину и высоту. Тематический выбор цвета поддерживает HSV, HEX, RGB, отмену и живое переключение дневного/ночного режима. Цветовые квадраты не содержат текста. Шрифт выбирается и ищется в одном редактируемом списке: можно ввести часть названия или полное название установленного шрифта. Размер текста от 1 до 60 px задаётся вводом или ползунком; при превышении лимита появляется предупреждение, значение ограничивается 60 px. Размер текста не меняет размеры кнопок или других элементов.

В **Деталях** выбирается каждый из 15 элементов: обложка, название, исполнитель, предыдущий трек, пауза/воспроизведение, следующий трек, повтор, закрепление, блокировка перемещения, клики насквозь, скрытие, меню, шкала, время и громкость. Для каждого доступны видимость, X/Y, ширина и высота. В обычном превью и в окне 1:1 нажмите на элемент, чтобы выбрать его. Перетащите его для перемещения или потяните за угол рамки для изменения размера. **Закрепить элемент** сохраняет его положение, размеры, видимость, цвета, шрифт и прозрачность при дальнейших изменениях; поля и перетаскивание блокируются до снятия закрепления. Размер корпуса ограничивается так, чтобы закреплённые элементы оставались внутри его границ. Контур формы обрезает вышедшие за него элементы: при выборе звезды или сердца расположение можно скорректировать вручную. Фон можно загрузить из PNG/JPG/BMP/GIF, выбрать заполнение, положение и непрозрачность. GIF проигрывается в превью и самом плеере.

Превью использует тот же рендерер, что и настоящий плеер. Масштаб фиксирован и указан рядом с размерами: изменение корпуса больше не вызывает автоматическую подгонку. Доступны ползунок масштаба, **100%**, разовая подгонка **Вписать** и прокрутка в обе стороны. **Превью 1:1** открывает макет в реальном размере. Название, обложка, время и состояния кнопок в мастерской демонстрационные, в плеере они берутся из выбранного музыкального приложения. Черновик сохраняется автоматически; **Сохранить пресет** добавляет вариант в **Созданные пресеты**, а **Применить** сохраняет его и сразу меняет запущенный мини-плеер. Плеер подтверждает применение конкретного файла; при ошибке прежний активный пресет восстанавливается. Если плеер ещё не установлен, он устанавливается из комплектного пакета. Старый установленный плеер обновляется из него с резервной копией, сохранением настроек и посторонних файлов.

Рандомизация собирает согласованные композиции: группы кнопок, информация о треке и шкалы располагаются рядами без наложений. Используются читаемые сочетания цветов, размеров текста и прозрачности; фон выбирается из уже загруженных файлов с небольшой непрозрачностью. Если есть закреплённые элементы, расположение и размеры всего макета сохраняются, а оформление меняется только у свободных элементов. **Вернуть предыдущий** возвращает предыдущий случайный вариант вместе с закреплениями.

**Сохранить как копию** создаёт отдельный вариант и открывает его для редактирования. В мастерской нажмите **Экспорт в файл** для сохранения `.vibepreset` или **Скопировать код** для передачи текстом. В разделе **Созданные пресеты → Мини-плеер** выберите **Импорт из файла** или **Вставить код**. Оба формата включают пользовательский фон или GIF. Для использования импортированного оформления на виджете нажмите **Применить**.

Активный пресет хранится в `Data/Customization/mini-player/active.json` и загружается при запуске плеера. Чтобы вернуться к обычной теме, откройте его **Кастомизацию**, выберите тему и сохраните её; отмена возвращает активный пресет. Изображения копируются в папку пресетов и сохраняют относительные пути при переносе хаба. Импорт ограничен 20 МБ, 4096×4096 пикселями и 180 кадрами GIF; суммарное число пикселей кадров ограничено 48 миллионами.

Выбор дневного и ночного режима из этого раздела убран. Значок солнца/луны возле `alpha` продолжает переключать хаб и окна настроек виджетов. Под кастомизацией находится раздел **Связь с OBS** с надписью **скоро будет, братва**.

Ссылка **GitHub ↗** под надписью **Всё на своём месте** открывает репозиторий проекта в браузере.

## Расположение файлов

```text
Выбранная папка/VibeWidgetsHub alpha/
  Launcher.exe
  Uninstall.exe
  Runtime/                 компоненты запуска, общие для лаунчера и виджетов
  Catalog/widgets.json     каталог
  Packages/mini-player.zip пакет для установки мини-плеера
  Widgets/mini-player/App/ установленный мини-плеер
  Data/mini-player/        настройки, оформление и горячие клавиши
```

При первом запуске мини-плеер копирует прежние настройки из `%LOCALAPPDATA%\MiniPlayer`, если в новой папке их ещё нет. Исходные настройки остаются на месте. Старую отдельную версию плеера лучше закрыть через её значок возле часов перед запуском новой.

Удаление виджета из лаунчера сохраняет его настройки для повторной установки. Кнопка удаления в настройках управляемого мини-плеера открывает эту же операцию в лаунчере. Полное удаление лаунчера доступно в его настройках и в установленных приложениях Windows; после подтверждения удаляются также установленные виджеты и их данные. Посторонние файлы в выбранной папке сохраняются.

Для обновления через полный установщик завершите хаб и плеер через меню возле часов, запустите новый установщик и выберите прежнюю папку хаба. Установщик также обновит уже установленный мини-плеер. Настройки, пресеты и добавленные пользователем файлы сохранятся.

Если указана сама папка `VibeWidgetsHub alpha`, вложенная копия не создаётся. Установка в прежнюю папку, где уже есть лаунчер, распознаётся как обновление, в том числе для старых установок с другим именем каталога.

В мини-плеере булавка управляет отображением поверх окон, а отдельный замок запрещает перемещение. В меню ПКМ доступны настройки, кастомизация и скрытие. Глазик скрывает плеер; вернуть его можно из трея, кнопкой **Показать** в лаунчере или горячей клавишей. В настройках есть отдельные сочетания для скрытия, показа, блокировки и разблокировки перемещения, закрепления и открепления.

Кнопка с изображением правой кнопки мыши открывает меню. Повтор циклически переключается между выключенным режимом, альбомом/плейлистом и одним треком; музыкальное приложение должно поддерживать эту команду через Windows. Ползунок внизу плеера меняет громкость выбранного источника; у браузера меняется звук всех его вкладок. Автопоказ при сворачивании также относится к выбранному источнику. Ручной показ или скрытие действует до следующего сворачивания или восстановления его окон.

Для каждой установки лаунчера одновременно открывается одно окно подтверждения удаления. При повторном нажатии это окно выходит вперёд и звучит стандартный сигнал Windows.

## Сборка

Сборка выполняется на Windows x64 с PowerShell 7 (с библиотеками Roslyn), .NET Desktop Runtime 10 и стандартным .NET Framework Windows. SDK для комплектного сценария сборки не требуется.

Из корня репозитория:

```powershell
pwsh -NoProfile -File .\Build-Launcher.ps1
```

При первой сборке скачиваются два официальных архива среды Microsoft 10.0.15. Перед распаковкой проверяются закреплённые SHA-512. Лицензии среды поставляются внутри папки Runtime. Готовый установщик появляется в `dist\WidgetLauncher-Setup.exe`; промежуточные файлы — в `.build`. Ключ `-RuntimeCache` позволяет использовать заранее скачанные архивы.

`Launcher\Launcher.csproj` и `Source\MiniPlayer.csproj` также содержат проекты для разработки с .NET SDK 10. Общий сценарий формирует пакет виджета, добавляет закрытую среду запуска, собирает оболочку запуска и один установочный EXE.

## Добавление виджетов

Каталог — массив объектов с полями `Id`, `Name`, `Description`, `Version`, `Package`, `Executable`, `Available`. `Id` — имя подпапки в `Widgets` и `Data`; пакет задаётся относительно `Packages`, исполняемый файл — относительно папки виджета. Пакеты распаковываются только внутрь папки виджета; абсолютные пути, переходы к родителю и ссылки отклоняются.

Текущий протокол запуска рассчитан на управляемые .NET-виджеты: среда запускает DLL рядом с EXE и передаёт `--data-dir`, `--launcher-root`, `--show-existing`. Для новых типов виджетов, включая OBS, потребуется отдельный адаптер запуска. Состояние экземпляра и команды закрытия/показа используют именованные объекты Windows; пример реализации находится в `Source\LauncherIntegration.cs`.
